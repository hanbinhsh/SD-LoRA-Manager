# Tag 浏览搜索优化

## 原因与调整

旧实现每次输入都同步遍历全表，每行重新读取表头来确定搜索列，并重复进行大小写、空格、下划线和标点规范化。合并词表越大，单次键盘事件阻塞越明显。

- `utils/tagsearchindex`：纯数据规范化与包含/整词/精确匹配，不读取控件或 model。
- `widgets/tagsearchproxymodel`：翻译表和用户 Tag 表共用；明确指定 Tag 与翻译列，加载或编辑时维护索引。
- 连续输入等待 180ms 后合并提交，Enter 跳过等待；清空搜索、切换匹配模式立即安排更新。
- 后台只读取不可变索引快照，每张表最多一个匹配 worker。新输入取消旧计算，旧结果不能覆盖新查询或重新加载后的数据。
- 主线程只应用匹配结果、更新 proxy 映射和状态提示；不因搜索重建表格或丢弃未保存编辑。
- 兼容新增、删除、编辑、重新加载及来源表变化；保留现有 CSV 顺序、表头数值排序、复制和保存行为。

## 重复逻辑清理

- CSV 保存、用户 Tag 导出共用 `TranslationCsv::escapeField`。
- 用户 Tag 统计复用 `TagUtils::parsePromptTags`，保留每图去重与特殊词过滤，并拒绝将 JSON 当作提示词。
- 全部/可见/选中用户 Tag 导出共用行读取；翻译信息加载与刷新共用查询逻辑。
- 合并词表按被修改的行跟踪未保存状态，不再每次编辑遍历全表；恢复原值会移除该行的修改标记。
- 普通编辑不再重复刷新用户 Tag 全表；保存后读取新的生效词表再更新。
- 修正切换词表时选择保存但保存失败后，下拉框与当前数据源不一致的问题。
- CSV 来源绝对路径每个文件只求一次，不再逐行重复构造。

## 验证

```powershell
cmake -S . -B build/codex-model-startup-verified -DBUILD_TAG_BROWSER_TESTS=ON
cmake --build build/codex-model-startup-verified --parallel 4
ctest --test-dir build/codex-model-startup-verified --output-on-failure
```

使用 Qt 6.11.1/MSVC Release。测试用例使用临时 CSV 和离屏控件，不启动主应用、不读取用户词表、不截图。

覆盖：大小写/空格与下划线、中文翻译、三种匹配模式、排除非搜索列、编辑/插入/删除/排序/重载、连续输入与过期结果、关闭期间的后台任务、合并来源优先级与多 CSV 回写、CSV 转义。

10 万行合成索引测试确认搜索期间不再读取源 model 或表头；本机一次运行中三次输入调用约 49 微秒，含 180ms 等待的整体搜索约 190ms。此计时不包含初始索引构建或实际窗口绘制，仅用于验证输入路径不执行全表工作，不作为真实词表的性能保证。

固定 UI、QSS 和原有词表格式未变；真实词表规模下的交互与视觉表现仍需实际使用验证。
